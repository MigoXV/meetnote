# MeetNote 客户端示例 demo01

独立的 React / TypeScript / Vite 客户端，用于连接**已经启动的 MeetNote 实例**，手工检查服务的全部公开业务能力。它不导入 MeetNote Python 包、不加载模型、不启动业务服务。

## 启动

需要 Node.js 22.12+ 和 pnpm。先单独启动要测试的 MeetNote 实例，再运行：

```bash
pnpm --dir examples/demo01 install
pnpm --dir examples/demo01 dev
```

浏览器打开 `http://127.0.0.1:5176`，填写服务根地址（默认 `http://127.0.0.1:8010`），点击“连接实例”。该地址应指向 MeetNote，不能填写主模型的 `/v1` 地址。

可在启动时设置默认地址；这只改变输入框初始值：

```bash
VITE_MEETNOTE_URL=http://127.0.0.1:8015 pnpm --dir examples/demo01 dev
```

构建和预览：

```bash
pnpm --dir examples/demo01 lint
pnpm --dir examples/demo01 build
pnpm --dir examples/demo01 preview
```

预览地址为 `http://127.0.0.1:4176`。开发和预览均提供本地 `/bridge` 流式请求转发，因此实例无需为本 demo 增加 CORS。**不能直接双击 HTML，或只用普通静态文件服务器托管 dist**，否则转发入口不可用。默认仅监听本机，不把此调试代理作为公网服务部署。

如果浏览器和 Vite 运行在不同机器上，实例地址以 **Vite 所在机器**能访问到的地址为准。本示例不代管实例鉴权配置。

## 测试路径

### 全文生成

1. 粘贴完整转写，或从实例载入样本。
2. 选择并调整能力顺序，填写请求 ID，点击“生成所选内容”。
3. 查看摘要、纪要、工作计划、润色正文和原始响应，可手动复制产物。
4. 使用“取消请求”中断长请求；断连由代理传递给实例。

请求契约为 `POST /v1/fulltext/generate` 的 `id / text / pipeline`。默认顺序为 `abstract → minutes → keywords → actions`；`polish` 需显式选择。`keywords` 目前固定为 `null`，页面明确显示占位状态。HTTP 200 携带 `message` 时按“存在失败提示”显示，不能被当作成功。

旧实例未声明 `fulltext_generate` 时，页面显示版本提示并禁用全文提交，其他已提供的接口仍可测试。

### 流式会话

1. 创建会话，或刷新列表并选择已有会话。
2. 手动提交文本、发言人、时间戳和片段 ID；失败保留 ID，便于原样重试。
3. 可载入服务端样本，设置片段间隔后逐段回放；支持暂停和继续。
4. 回放或手动输入完毕后点击“结束输入”，等待真实终态。
5. 查看纪要、可撤回预览、事实、原文、来源、修订和模型调用统计。
6. 暂停或恢复 SSE，使用补发游标重连；最后确认释放会话。

“已接受入队”只表示请求被服务接收；消费者已取片段数和实际剩余字符分别展示。未完成纪要标注为可撤回预览。暂停订阅不会取消实例处理；退出或刷新页面也不会自动删除服务端会话。明确点击“确认释放”才发送 DELETE。

SSE 使用流式 fetch，以便传递 `Last-Event-ID`。支持多行 data、分段 UTF-8 和 CRLF 帧；完整快照与增量事件分别处理，过期游标由实例回退快照。页面保留最近 60 条事件，每条最多显示 2,000 字符；最近请求只记录方法、路径、状态码和耗时。

### 实例诊断

检查健康状态、模型、快照契约、保留时间、持久化声明、接口目录和 OpenAPI 定义；可直接打开实例自己的交互文档。请求记录只保留最近 60 项。

## 内存与连接边界

所有输入、产物、事件、实例地址和主题偏好仅保存在当前页面内存中，不使用 localStorage、sessionStorage、IndexedDB、Cookie 或文件记录。代理直接传递请求和 SSE，不记录正文、不缓存产物。刷新后本地内容清空，实例会话按照服务端策略继续保留。

重新连接会卸载旧实例工作区并清空本地结果。正在生成、提交或回放时禁止切换实例。服务不在线、样本读取失败、单项能力失败、排队失败和 SSE 中断分别显示错误并提供重试路径。

## 设计与状态

采用 MANAS 的实时工作台主范式、文档阅读辅助范式。默认白垣，可切换苍渊；双主题共用组件与结构。`src/brand-tokens.css` 直接取自苍渊·白垣 v1.1 锁定 Token，`style.css` 仅增加主按钮别名及局部布局，不修改品牌色值。

| 真实状态 | 来源 | 页面反馈与恢复 |
| --- | --- | --- |
| 未连接 / 检查中 / 失败 | 健康检查与实例信息 | 输入地址、连接、明确错误与重试 |
| 全文等待 / 生成中 / 返回 / 失败提示 / 取消 | 实际 fetch 和响应 message | 禁止重复提交、可取消、保留返回内容、可重新提交 |
| 接收中 / 收尾 / 完成 / 失败 / 取消 | 服务端会话 status | 按状态开放提交与收尾；快照、错误和释放始终可达 |
| 订阅连接 / 中断 / 暂停 / 结束 | SSE 传输生命周期 | 与会话状态分开；可恢复、补发或刷新快照 |
| 回放进行中 / 暂停 / 已接受全部 | 逐段请求回执 | 进度只在接受后推进；原 ID 重试；结束后由用户收尾 |

URL 和正文使用长输入，日期与片段间隔使用紧凑参数，能力使用复选与顺序按钮，生成与结束输入作为任务主操作。桌面并排输入与结果；中窄屏按输入、操作、结果顺序排列，保留全部功能。提供标签、键盘焦点、跳转工作区入口、状态文字和 reduced-motion 支持。

## 验证

```bash
pnpm --dir examples/demo01 test
pnpm --dir examples/demo01 test:e2e
```

Node 测试检查代理转发、错误和取消；浏览器行为测试使用明确的网络替身验证客户端状态，不启动业务服务，也不能代表模型质量。浏览器测试关闭截图、视频和 trace，避免把会议内容写入产物文件。真实实例验证需另行连接正在运行的服务。
