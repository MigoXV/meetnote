# BF16 决策替换的效果与精度对照

日期：2026-10-02。比较旧方案（全部任务由现有 spark25 Responses 主模型处理）与 BF16 双模型（fields、reconcile 及证据选择由 qwen-decider 处理）。回退关闭，权重与业务 Prompt 未修改；没有调参后重报同一轮结果。

## 当前结论

**跑通已经证明，但现有 BF16 决策替换不能据此认定质量达标。**独立决策题提升，完整短流程却出现回归，应优先看后者。用户此前选择的 BF16 默认精度保持不变；本次仅报告证据，没有自动切换方案。

## 36 道独立决策题

| 项目 | 旧方案 | BF16 双模型 |
|---|---:|---:|
| 负责人核验 | 11/12 | 11/12 |
| 期限核验 | 12/12 | 11/12 |
| 关系判断 | 7/12 | 11/12 |
| 合计 | 30/36（83.3%） | 33/36（91.7%） |
| 异常／无法决策 | 0 | 1，已计为错误 |

BF16 失败：`contact_only` 回答不确定导致显式失败；`due_discussion` 错把“今天别猜”当任务期限；`different_subject` 错把另一个事项的取消当成当前事项撤销。旧方案还存在主备班错配及多种关系误判。

此项通过相同领域 payload 分别走两个后端的既有适配方式，属于小规模合成回归题，不是独立的新生产测试集。不将 +8.3 个百分点外推为真实会议总体提升。

## 36 个完整短流程

两边走同一个 MeetingEngine 和既有校验器。旧方案产生 60 次抽取请求；BF16 侧对这 60 次请求全部命中内存复用，新增抽取请求为零。仅严格相同的任务指令、上下文和输出 Schema 可以复用，决策请求本身不复用。

| 结果 | 旧方案 | BF16 双模型 |
|---|---:|---:|
| 通过 | 36/36（100%） | 31/36（86.1%） |
| 回归场景 | — | 5 |
| 改善场景 | — | 0 |

这 5 个场景旧方案通过、BF16 失败：

| 场景 | 实际影响 |
|---|---|
| conflict | 原文明示分歧，账本未标记冲突 |
| late | 明确后续决定未关闭旧提议／未决事项 |
| deadline_scope | “今天别猜”被写成核实任务的期限 |
| field_batch | 明确点名的第三人称负责人被误删 |
| pending_schedule | 正式日期明确后，旧的待确认状态仍处于现行清单 |

这组结果说明决策替换影响了最终结构和状态，不只是概率数值不同。36 个短流程是预先已有的语义回归检查；通过率不等于全部生成文本的事实精确率或召回率。

## 完整会议的实际效果

复跑 `product_clean` 的全部 24 段，先运行 BF16，再运行旧方案；推理结束后才读取该场会议的人工标注。BF16 完成并产生 55 条事实，剩余原文为零，无最终错误或降级警告。这里的完成状态不是语义质量得分。

人工逐项核对 9 项参考记录（3 项事实、2 项决定、3 项行动、1 项未决问题），两边均能在完整事项清单中找到相应内容，三项标注行动的负责人和期限均保留。**这是 9 项关键信息的覆盖检查，不是全文精确率 100%，也不代表简明正文覆盖齐全。**

进一步阅读原文、结构字段和最终正文后发现：

- 明确的替换退步：`s14` 的第二条行动，在旧方案中保留负责人，BF16 将该负责人清空。这条额外行动不在上述 9 项关键标注中，说明只看少量标注覆盖会漏掉真实错误。
- 两边的事实清单均存在脱离上下文的代词式事项，被独立列为正式结论；信息自足性不足。
- 失败重试问题已有后文方案，却仍有对应旧问题处于待确认状态。两边清单均存在这一问题，不能全部归因于 BF16。
- BF16 的简明正文没有纳入灰度日期及其前置条件，但完整清单中有。正文选取和信息优先级仍需改善。
- 同一未决问题被多次列出，存在重复；完整清单较长，不应把“有结果”当作交付质量验收。

因此该场会议主要信息没有整体丢失，但仍有字段丢失、状态收敛和正文组织问题。结合 36 个短流程的 5 项回归，目前建议继续试验和定位错误，不把它宣布为旧方案的质量等价替代。未自动修改用户选定的 BF16 配置，未为提高本轮分数修改 Prompt、权重或回退规则。

## 复现及口径

在 BF16 决策服务启动且 ready 后执行：

```bash
poetry run meetnote evaluate-decisions --backend both
poetry run meetnote compare-decisions
poetry run meetnote review-quality --sample product_clean --details
```

主模型必须为真实 Responses；程序检查决策服务为 BF16 vLLM，并输出服务指纹。此次使用指纹 `cd4a4c86acd7f52a064025802924cce86c2b0cb0ea0d3b34ca108cb54997e979`，PyTorch 2.9.1、vLLM 0.14.1、Transformers 4.57.6。模型来自 `decider-domain-v3-hf` 的 BF16 导出。

会议输入、抽取缓存、模型产出和事件仅在内存中，详细内容只在终端复核，不写文件。人工标注仅在完整会议推理结束后由评测器读取，不进入模型 Context。模拟器输出明确标为 SIMULATED，本报告的真实结果没有使用模拟器。

这轮以质量为目标，没有执行公平的速度对照。尤其不能拿复用了抽取结果的第二轮耗时宣称系统加速。两组评测采用不同入口与语料，不合并分母；样本量小且为开发合成集，不报告统计显著性或生产总体精度。
